# Estado de las herramientas de IA (catálogo completo)

Las **21 herramientas** de `components/tools/catalog.ts` (12 estudiante + 9 profesionales, agrupadas por `category`) están implementadas. Detalle completo de cada una, con qué se verificó y por qué, en `PLAN.md` (bitácora en la sección "0. Estado del proyecto") y `docs/AI.md`. Resumen para orientarse rápido:

- **Patrón por herramienta**: `lib/ai/prompts/<tool>.ts` (prompt + schema Zod) → `lib/documents/analyze/<tool>.ts` o `lib/tools/<tool>/actions.ts` directo si no hay documento → `components/tools/<tool>-form.tsx` → `app/(app)/tools/<slug>/page.tsx`. Todas las llamadas a IA pasan por `lib/ai/service.ts` (nunca importar `GeminiProvider`/`GroqProvider` directo).
- **Con documento subido (DOCX)**: APA, Analizador de escritura, Corrector de redacción, Analizador de CV, Analizador de bibliografía, Analizador de documentos, Analizador de riesgos y contratos, Resumir, Preparador de exposiciones, Generador de presentaciones, Flashcards, Simulador de exámenes → todas restringidas a `.docx` (PDF/XLSX/CSV solo tienen extracción de texto para XLSX/CSV vía `lib/documents/extract/spreadsheet.ts`, no para PDF — `pdf-lib`/`pdfjs-dist` siguen sin instalar). El Simulador de exámenes es el único con calificación híbrida: opción múltiple determinista, preguntas abiertas calificadas por IA (ver `PLAN.md` sección 2 para el detalle de seguridad de no exponer respuestas correctas al cliente antes de calificar).
- **Con documento subido (XLSX/CSV)**: Analizador de Excel/CSV, Generador de informes — usan `lib/documents/extract/spreadsheet.ts` (estadísticas deterministas) + IA solo para la narrativa, nunca para recalcular números.
- **Sin documento (texto/datos pegados directo)**: Chat con documentos (tiene documento pero es conversación persistida, no análisis único), Ayudante de programación, Asistente de correos, Generador de CV, Resumen de reuniones, Generador de documentos.
- **Sin IA en absoluto** (deterministas puros, por diseño): Generador de referencias APA (`lib/citations/apa-reference.ts`, formato APA 7 es una regla fija) y Analizador de bibliografía (`lib/rules/bibliografia.ts`, comparar citas vs. referencias es un hecho verificable por texto).
- **Generan un DOCX real descargable** (vía la librería `docx`, ya instalada, sin dependencias nuevas): corrección de formato APA (Fase 7), Generador de documentos, Generador de informes (con tabla de estadísticas real).
- **Decisiones éticas explícitas tomadas sin consultar, documentadas en el código y en `PLAN.md`**: el Analizador de escritura NO es un detector de texto generado por IA (indicadores de estilo únicamente, con disclaimer visible); el Analizador de documentos NO da asesoría legal ni evalúa riesgo de cláusulas (solo extracción factual neutral); el Analizador de riesgos y contratos SÍ señala cláusulas atípicas a propósito, pero nunca en términos de "legal/ilegal" o "válido/inválido" — solo desviación de prácticas comunes, con disclaimer obligatorio en la UI; los generadores (CV, documentos, reuniones) tienen instrucción explícita de no inventar datos faltantes (usar placeholders/"No especificado" en vez de fabricar).
- **`xlsx` (SheetJS)** está instalado desde `cdn.sheetjs.com`, NO desde npm — el paquete de npm tiene una vulnerabilidad de severidad alta sin fix (prototype pollution + ReDoS) que SheetJS solo parchó en su propio dominio de distribución. Ver `package.json` línea de `xlsx` y sección 1.1 de `PLAN.md`.
- **Modelo de Groq**: `openai/gpt-oss-120b` (no `llama-3.3-70b-versatile`, que Groq retiró — verificado empíricamente el 2026-09-21). `GROQ_API_KEY` configurada como fallback real de Gemini; el límite gratuito de Gemini (20 solicitudes/día) se agota fácilmente en sesiones de desarrollo con pruebas reales, momento en el que `AIService` cae a Groq automáticamente — comportamiento esperado, no un bug.

# Planes (Free/Pro) y pagos con Yape

- `profiles.plan` (`'free'`/`'pro'`) + `profiles.pro_expires_at` — Pro es un **pago manual recurrente sin cobro automático** (Yape, S/ 5/semana), así que expira a los 7 días de la aprobación, no es "para siempre". Un trigger (`protect_profile_plan`, en las migraciones `20260922000001`/`20260922000002`) bloquea que el cliente autenticado normal escriba cualquiera de las dos columnas — solo `service_role` puede, vía el panel de admin o el Table Editor de Supabase.
- `lib/config/plans.ts`: `PRO_TOOL_SLUGS` (6 herramientas: Generador de CV, Generador de documentos, Generador de informes, Analizador de documentos, Analizador de riesgos y contratos, Generador de presentaciones, Simulador de exámenes — revisar el archivo, la lista puede crecer), `hasProAccess(profile)`/`canAccessTool(slug, profile)` reciben el perfil completo (no solo `plan`) para poder comparar `pro_expires_at`. Gating en **dos capas** por cada herramienta Pro: `components/plans/pro-gate.tsx` en el `page.tsx` (oculta el formulario tras `UpgradePrompt`) + el mismo chequeo repetido dentro del Server Action correspondiente — nunca confiar solo en que la UI esté oculta.
- **Flujo de pago** (sin API de Yape — no existe una pública de autoservicio, requeriría RUC + convenio con BCP): el usuario yapea al QR de `public/yape-qr.jpg`, sube una captura en Ajustes (`components/plans/payment-form.tsx`, tabla `payment_requests`, bucket privado `payment-proofs`), y un admin la aprueba/rechaza en `/admin/pagos`. Admin identificado por `ADMIN_EMAILS` (env var, comparación server-side) — no hay columna `is_admin` en la base de datos a propósito, para no tener que proteger una segunda columna contra auto-escritura.
- `lib/supabase/admin.ts` es el **único** cliente `service_role` del proyecto — bypassa RLS por completo, exclusivo para `/admin/pagos` (leer comprobantes de todos los usuarios, activar el plan). Nunca importarlo fuera de ese flujo ni exponerlo al cliente.
- **Supabase Realtime** habilitado por primera vez (`payment_requests`, migración `20260922000003`) para que `components/plans/pro-celebration.tsx` festeje (confeti + banner) apenas el admin aprueba, sin que el usuario recargue la página — Realtime respeta la RLS existente (`select own`) automáticamente, así que cada usuario solo recibe el cambio de su propia fila.
